# Program status (OSC 7501)

Termy supports revision 0.3 of the [Program Status Protocol](https://www.superlogical.com/rex/docs/build/program-status).
Programs report `idle`, `working`, `blocked`, `done`, or `error`, with optional
progress, application name, task title, and message. No shell plugin is required.

```sh
printf '\033]7501;state=working:app=example:progress=40\033\\'
printf '\033]7501;state=blocked:kind=permission:app=example:msg=QXBwcm92ZT8=\033\\'
printf '\033]7501;state=done:app=example:msg=RmluaXNoZWQ=\033\\'
printf '\033]7501;state=clear\033\\'
```

The blocked message above is “Approve?”; the done message is “Finished”.
`msg` and `title` use standard base64 UTF-8, with optional padding. Reports can
end in either BEL (`\007`) or ST (`\033\\`). Sending `OSC 7501 ; ? ST`
produces the fixed reply `ESC ] 7501 ; ? ESC \`. Ordinary reports produce no reply.

## Desktop presentation

With `progress_indicator_enabled` enabled, each pane displays its most urgent
active status, application, task title or id, percentage (when provided), and
message. Tab headers show a working dot, a question mark for blocked tasks, a
checkmark for completion, or an exclamation mark for failure. Blocked tasks take
precedence over errors, completed tasks, and working tasks, in that order;
equally urgent records favor the most recently updated one within a pane.
Idle records are retained without a badge. Messages are plain text, shortened
to fit the pane, with invisible direction/formatting characters removed.

The pane progress bar uses the selected working/blocked/error record.
OSC 9;4 remains independent and is used when no active OSC 7501 record exists.
The setting controls presentation only; protocol detection and tracking remain
enabled. No system notifications or sounds are generated by these reports.

## Records and lifetime

- Reports replace a record completely; omitted fields do not retain old values.
- No `id` means the root record. Slash-separated ids define task hierarchies.
  A missing `app` inherits from the nearest ancestor that supplies one.
- `state=clear:id=build` removes `build` and its descendants, but not `builder`.
  `state=clear` without an id removes all records.
- A shell prompt (OSC 133 `A`) or attached process exit removes working and
  blocked records. Idle, done, and error records remain until replaced or cleared.
- Alternate-screen switches and soft reset preserve records. Full reset (RIS)
  clears them all.
- Records are capped at 256 per terminal; the least recently updated record is
  evicted when a new id exceeds that cap. All protocol field and decoded-text
  limits are enforced before any update is applied. Both terminators use the
  conservative ST-sized 4096-byte sequence limit.

Termy's native multiplexer retains current snapshots across detach/reattach.
This change uses session protocol version 2. Close existing version-1 hosts with
their matching Termy binary before upgrading; Termy does not replace a live
incompatible host. External multiplexers must forward OSC 7501 reports and
queries for this feature to work through them.

## Embedding

- Rust engine: `program_status()` reads the current snapshot;
  `take_program_status()` returns a snapshot only after a change, including an
  empty snapshot when the last record disappears. Call `process_exited()` when
  a host-managed process exits. Termy's native PTY runtime does this automatically.
- Native runtime: `TerminalEvent::ProgramStatus(Vec<ProgramStatusRecord>)`.
- C ABI: event kind `13`, with a UTF-8 JSON array in `payload`.
- `@termysh/core`: `{ type: 'programStatus', records }` from `takeEvents()`.
- `@termysh/web`: `onProgramStatus(records)` and `processExited()`.
  Call `processExited()` when the server reports process exit. Low-level core
  hosts should then drain events as usual.

Snapshots replace the previous snapshot and are coalesced between drains.
Records contain `id`, `state`, `kind`, `progress`, `app`, `title`, and `msg`;
optional JSON fields are `null`, root `id` is `""`, and `app` includes resolved
inheritance. Display strings remain untrusted terminal content and must be
rendered as text by embedding hosts.
