# Termy 1.0.0-rc.8

Release candidate prepared from the changes since `v1.0.0-rc.7`.

## Before upgrading persistent sessions

If you use `multiplexer_enabled = true`, finish or save your work and close
existing persistent terminal sessions using the older Termy version before
upgrading. Quitting the app alone leaves these sessions running.

After finishing the work in those sessions, run `termy mux shutdown` using
the older installation, then quit it and upgrade. This stops the old host
and its remaining terminal processes; closing tabs alone does not stop the host.

This candidate uses session-host protocol version 3. An older version 2 host
cannot accept the new terminal launch configuration; Termy rejects the
connection instead of decoding incompatible data. Start fresh sessions with
the new version after closing the old ones.

## Changes

- Display inline images from applications using iTerm2's OSC 1337 protocol,
  including sizing, aspect ratio preservation, and multipart uploads.
- Correct Kitty image placement, stretching, cursor movement, and replies.
  Accept leniently padded payloads emitted by tools such as chafa.
- Choose the terminal identity in Settings or with `term_program = ghostty`
  or `term_program = termy` in the config. The default remains `ghostty` for
  application compatibility. Termy mode reports `TERM_PROGRAM=termy` and
  removes an inherited `TERM_PROGRAM_VERSION`.
- Improve Windows support with WinUI native tabs, PowerShell shell
  integration, ConPTY process tracking, CLI integration, and installer fixes.

## Testing this candidate

Try image output, changing terminal identity in a newly opened terminal, and
closing and reopening the app with persistent sessions enabled. Report the
operating system, architecture, and reproduction steps with any issue.

From a checkout inside Termy on macOS or Linux, run:

```sh
python3 crates/desktop_app/examples/inline_images_smoke.py --report /tmp/termy-images.json
```

The script checks Kitty replies, cursor advancement and preservation for both
protocols, and leaves the images visible for resizing and visual inspection.

This is a pre-release. The publication workflow must mark it as such so stable
release finalization and AUR publication do not run.
